# LLM 模型网关 · 学习文档

> **本页速览**
> - 这个项目是**所有上游大模型调用的唯一入口**:业务侧不直连 DeepSeek,一律打到这里。
> - 网关负责四件事:**渠道路由 / 限流 / 熔断 / Token 计量**。当前已实现前两件。

> - 想看代码在哪:`D:\java\llm-gateway`,主代码 21 个类 ≈ 2200 行。

## 这个项目解决什么问题

假设你有一堆业务系统(订单平台、客服系统、Agent),它们都要调用大模型。
如果每个系统都自己写一遍"调 DeepSeek"的代码,会发生什么:

```text
订单平台 ──┐
客服系统 ──┼── 各自直连 ──→ DeepSeek / Moonshot / 通义
Agent  ──┘
        │
        ├─ 每家厂商协议格式不一样 → 每个系统都要写一遍适配
        ├─ API Key 散落在 N 个项目里 → 泄漏面 = N 倍
        ├─ 没人限流 → 某业务写错循环,把额度刷爆,全公司一起挂
        ├─ 换一家厂商 → N 个系统一起改
        └─ 花了多少钱 → 没人说得清
```

**网关就是把上面这些"人人都要操心的事"收拢到一个地方:**

```text
订单平台 ──┐
客服系统 ──┼──→ LLM 网关 ──→ 渠道 A (DeepSeek)
Agent  ──┘      (只认这一套)  └→ 渠道 B (Moonshot)
```

一句话记住:**网关的价值 = 把厂商差异关在门内。**

## 怎么用这套文档

**每一页都是同一个结构**,打开就能对上:

```text
# 页标题
> 本页速览          ← 3~5 条,10 秒抓住重点
> 导航              ← 上一页 / 下一页 / 相关页,点着走

## 一句话职责
## 为什么需要它      ← 先讲"不做会怎样",再讲怎么做
## 关键片段逐行解释
## 值得学习的点
## 相关页
```

**三个使用要点:**

1. **不用按顺序读。** 每页都自包含,看到不懂的术语,点链接过去,不用回头补前一页。
2. **每页顶部的「本页速览」就是这一页的全部结论。** 只想知道"这类是干嘛的",看速览就够了。
3. **每页底部的「导航」是唯一的翻页入口。** 不用回目录。

> ⚠️ **文档里出现的行号/类名以 `main` 分支为准**(对应 G4 提交 `03e18ee`)。

## 当前实现了什么、没实现什么

**读文档前先知道边界,免得找一个不存在的东西:**

| 能力 | 状态 | 在哪看 |
|---|---|---|
| 协议归一(对外 OpenAI 格式) | ✅ 已实现 | [03-对外契约](01-modules/03-对外契约/_index.md) |
| 多渠道 + 按请求路由 | ✅ 已实现 | [02-上游渠道抽象](01-modules/02-上游渠道抽象/_index.md) |
| SSE 流式 + 取消传播 + 空闲超时 | ✅ 已实现 | [02-flows/流式请求处理流程](02-flows/流式请求处理流程.md) |
| Redis + Lua 令牌桶限流 | ✅ 已实现 | [06-限流](01-modules/06-限流/_index.md) |
| **熔断 + 错误分类** | ⬜ **未实现** | 代码里搜不到 `Resilience4j`,别找 |
| **渠道管理 / 加权路由** | ⬜ **未实现** | 现在只有"按名字选渠道",没有权重 |
| **Token 计量 / 预扣结算** | ⬜ **未实现** | `Usage` 字段是预留的,没有实际计费 |
| **Docker Compose / 可观测** | ⬜ **未实现** | 仓库里没有 `docker-compose.yml` |

> **为什么文档要写"没实现"**:一个只讲"有什么"的文档,会让你在面试或改代码时
> 以为某个能力存在。**诚实的边界比完整的功能列表更有用。**
