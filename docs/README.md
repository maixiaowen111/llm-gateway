## 这个项目解决什么问题

假设你有一堆业务系统(订单平台、客服系统、Agent),它们都要调用大模型。
如果每个系统都自己写一遍"调 DeepSeek"的代码,会发生什么:

```text
订单平台 ──┐
客服系统 ──┼── 各自直连 ──→ DeepSeek / Moonshot / 通义
Agent  ──┘
        │
        ├─ 每家厂商协议格式不一样 → 每个系统都要写一遍适配
        ├─ API Key 散落在 N 个项目里 → 泄漏面 = N 倍
        ├─ 没人限流 → 某业务写错循环,把额度刷爆,全公司一起挂
        ├─ 换一家厂商 → N 个系统一起改
        └─ 花了多少钱 → 没人说得清
```

**网关就是把上面这些"人人都要操心的事"收拢到一个地方:**

```text
订单平台 ──┐
客服系统 ──┼──→ LLM 网关 ──→ 渠道 A (DeepSeek)
Agent  ──┘      (只认这一套)  └→ 渠道 B (Moonshot)
```

一句话记住:**网关的价值 = 把厂商差异关在门内。**

## 怎么用这套文档

**每一页都是同一个结构**,打开就能对上:

```text
# 页标题
> 本页速览          ← 3~5 条,10 秒抓住重点
> 导航              ← 上一页 / 下一页 / 相关页,点着走

## 一句话职责
## 为什么需要它      ← 先讲"不做会怎样",再讲怎么做
## 关键片段逐行解释
## 值得学习的点
## 相关页
```

**三个使用要点:**

1. **不用按顺序读。** 每页都自包含,看到不懂的术语,点链接过去,不用回头补前一页。
2. **每页顶部的「本页速览」就是这一页的全部结论。** 只想知道"这类是干嘛的",看速览就够了。
3. **每页底部的「导航」是唯一的翻页入口。** 不用回目录。

> ⚠️ **文档主体写于 G1–G4(对应提交 `03e18ee`)**,G5–G9 的类当时还不存在。
> 行号/类名以当前 `main` 为准;"哪些能力已经实现"以本页状态表和根 README 为准。
> 两者冲突时,**信代码和测试**,不要信旧文档。

| 熔断 + 错误分类 + 同组故障转移 | ✅ 已实现 | 源码 `resilience/`、`exception/ErrorClassifier.java` |
| 渠道启停 / 权重 / 管理接口 | ✅ 已实现(状态在单实例内存) | 源码 `routing/ChannelStateRegistry.java` |
| 积分预扣 + 按真实 usage 结算 | ✅ 已实现 | 源码 `billing/` |

| 客户端 API Key 鉴权 | ❌ **未实现** | `X-Client-Id` 可伪造;管理端只有共享 token |

| 精确匹配缓存 / MySQL / Grafana 面板与告警 | ❌ **未实现** | 只在设计里出现过,不要当成已有能力 |
