## 路径 A:2 小时看懂这个项目在干什么

**适合**:刚拿到代码,想先建立整体印象。

| 顺序 | 读什么 | 读完能回答 |

| 2 | [架构总览](架构总览.md) | 一次请求经过哪些闸门、为什么是这个顺序 |
| 3 | [M2 _index](../01-modules/02-上游渠道抽象/_index.md) | "网关不认识厂商"是什么意思 |
| 4 | [类-Provider](../01-modules/02-上游渠道抽象/类-Provider.md) | 那个只有 3 个方法的接口到底约束了什么 |

## 路径 B:彻底搞懂(推荐,但慢)

**适合**:目标是"面试时能接住任何追问"。

按模块顺序走,**每个模块内部先读 `_index.md` 建立全貌,再读类页**。

### 阶段 1:地基(M1 + M2)—— 约 1.5 小时

```text
M1 骨架与配置
  类-LlmGatewayApplication   → 为什么启动类可以这么空
  配置-pom.xml               → 三个依赖坑:webflux/web、阻塞 Redis、WireMock standalone
  类-WebClientConfig         → 两种超时的区别(连接超时 vs 读超时)
  配置-application.yml       → 每个默认值背后的取舍

M2 上游渠道抽象 ★
  类-Provider                → 接口里为什么不能出现 JsonNode
  类-ProviderRegistry        → 渠道不存在为什么是 400 不是 502
  类-ProviderProperties      → 配置怎么绑定成对象
  类-ProviderConfig          → 装配逻辑
  类-OpenAiCompatibleProvider → 最长的一个类,协议归一在这
  流程-渠道路由               → 一次路由的完整过程
```

**阶段 1 自检**:
1. 在 `ChatController` 里搜 `"deepseek"`,为什么应该是零结果?
2. 连接超时和读超时分别管哪一段?为什么不能设成同一个数?
3. 渠道名重复时,"后者覆盖前者"为什么是错的?

### 阶段 2:契约与入口(M3 + M4 + M5)—— 约 1.5 小时

```text
M3 对外契约
  契约-OpenAI兼容约定        → 先读这个,理解"为什么对外必须是这套格式"
  类-ChatCompletionRequest   → 入参承诺
  类-ChatCompletionResponse  → 出参承诺
  类-ChatCompletionChunk     → 流式出参(和上面长得像但不一样)
  类-OpenAiErrorResponse     → 错误也是契约的一部分

M4 请求入口
  类-ChatController          → 流式/非流式怎么分流
  类-PingController          → 看起来最没用,其实是哨兵

M5 错误处理
  类-UpstreamExceptionHandler → 三种异常怎么收口
  流程-错误如何变成OpenAI格式
```

**阶段 2 自检**:
1. 为什么 `/ping` 看起来没用却必须留?
2. 成功是 OpenAI 格式、失败是 Spring 白板页,问题出在哪?
3. 上游返回 4xx 和 5xx,网关分别该回什么?

### 阶段 3:限流(M6)—— 约 2 小时,**含金量最高**

```text
M6 限流 ★
  类-RateLimitProperties     → 五个配置项各自控制什么
  类-RateLimitConfig         → ★ 启动自检:为什么连不上 Redis 要拒绝启动
  脚本-token_bucket.lua      → ★★ 全项目最该读懂的一百行
  类-RedisTokenBucketLimiter → 怎么调用 Lua、怎么处理异常
  类-RateLimitDecision       → 三态的意义
  类-RateLimitWebFilter      → 限流在哪一层生效、怎么识别客户端
  流程-一次被限流的请求
```

**阶段 3 自检**:
1. 为什么用令牌桶,而不是"每分钟最多 N 次"?
2. 为什么限流逻辑必须写在 Lua 里,不能"先 GET 再 SET"?
3. `fail-open` 选 true 还是 false,是技术决策还是业务决策?

### 阶段 4:测试验证(M7)—— 约 1.5 小时

```text
M7 测试验证 ★
  测试-契约测试              → 用假上游证明协议归一
  测试-流式与取消传播         → 证明"用户关页面,上游连接真的断了"
  测试-路由与注册表           → 证明 SPI 不是多余的
  测试-限流与并发             → ★ 32 并发只放行 5 个
  测试-对照组NaiveTokenBucket → ★ 证明"为什么必须用 Lua"
```

**阶段 4 自检**:
1. 跑测试为什么不需要 API Key、不花钱?
2. 怎么证明"取消传播"真的生效了,而不是看起来生效?
3. `NaiveTokenBucket` 在测试里扮演什么角色,为什么要有它?

### 阶段 5:跨模块流程(02-flows)—— 约 40 分钟

- [启动流程](../02-flows/启动流程.md)
- [非流式请求处理流程](../02-flows/非流式请求处理流程.md)
- [流式请求处理流程](../02-flows/流式请求处理流程.md)

**这三页是"把所有模块串起来"的地方** —— 单独看懂了每个模块,
但不知道它们怎么协作,就还是答不出"完整链路"这类问题。

## 三条路径的共同前提

不管走哪条,**下面三件事是绕不开的**,建议一开始就建立肌肉记忆:

1. **打开 `ChatController.java` 搜 `DeepSeek`** —— 零结果是这个项目的验收线。
2. **任何"为什么这么设计"的问题,先问"不这么做会怎样"** ——
   这个项目里每一个设计决策,都是被一个具体的失败场景逼出来的。
3. **遇到"环境报错"先验证事实,再相信上层工具的诊断** ——
   见 [配置-pom.xml](../01-modules/01-骨架与配置/配置-pom.xml.md) 里那个"没有错误信息的 400"。
